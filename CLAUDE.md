# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**drift** — a continuous generative music broadcast in the browser. No build step, no dependencies, no framework:

- `index.html` — page shell, all CSS, UI chrome (masthead, now-playing colophon, debug panel, "tune in" veil)
- `js/*.js` — the code, split by concern into plain classic `<script>`s loaded in dependency order (see Architecture). They share one global lexical scope — a top-level `const`/`let`/`function` in one file is visible in the next — so there are **no imports or `window.` qualifiers**; this is deliberate (ES modules would break `file://` loading). When adding a global that another file uses, mind the load order in `index.html`.

Run it by opening `index.html` in a browser (or any static server, e.g. `python3 -m http.server`). Audio requires a user gesture, so playback starts via the "tune in" button. Append `?debug` to the URL (or press `` ` ``) to open the debug panel.

## Core invariant: determinism from UTC time

Every musical and visual event is a **pure function of UTC wall-clock time** so that all listeners worldwide hear the identical moment of the same endless piece. This is the load-bearing design rule — preserve it in any change:

- All randomness must come from the seeded PRNG helpers (`R`, `rand`, `pick`, `wpick`, `vnoise`), keyed by stable identifiers like generation id / pulse index (e.g. `rand('ml', g, p)`). Never use `Math.random()` for anything audible or musically meaningful (it's only used for noise/impulse buffer sample data, where the exact samples don't matter).
- Time is expressed in seconds since `ORIGIN` (broadcast epoch, 1 Jan 2026 UTC) via `wallNow()`, which includes `debugOffset` for simulated time travel. Always use `wallNow()`, never `Date.now()` directly, for anything musical or visual.
- Broadcast time is converted to AudioContext time by adding `ctxOff` (recomputed each tick).

## Architecture

One concern per file, loaded in this order (each is a classic script with its own `'use strict'`; internal subsections keep their `/* --- name -- */` banners):

1. **`js/core.js` — time + deterministic randomness** — `ORIGIN`, `wallNow()`, `debugOffset`; the xmur3/mulberry32 PRNG and string-keyed helpers for music (`R`, `rand`, `pick`, `wpick`, `vnoise`); separate fast integer-hash noise (`ih`, `vn`, `fbm`) for per-frame visuals (avoids string hashing per frame — keep that split). Foundation everything else keys off.
2. **`js/theory.js` — timeless music primitives** — modes, odd meters, euclidean rhythms (`euclidHit`), `mtof`, `NOTE_NAMES`, and the chord/degree math: `chordAt(g, ci, P)` (tertian/quartal stacks, deterministic per generation+index), `degreeToMidi`, `fold`, `padVoicing`, `snapToChord`. Pure functions over a generation's params; no audio, time, or DOM.
3. **`js/structure.js` — the broadcast's form over time** — **Generations**: each UTC hour is deterministically cut into 2–5 segments of 10–30 minutes that tile it exactly (`hourSegs(e)`, feasibility-clamped draws); a generation's id is `hourIndex * GEN_SLOTS + segmentIndex`. `genAt(w)` finds the segment sounding at broadcast time `w`; `genAfter(g)`/`genPrev(g)`/`genSeg(g)` iterate/resolve segments. Also owns **biome selection** (`P.biome`, one of `BIOME_IDS` = hills/ocean/forest/coast/snow/sky, rendered by visual.js): deterministic per generation and guaranteed to differ from the previous one — anchored per UTC day (the day's first generation free-picks, later ones step a seeded non-zero offset off `genPrev`'s biome), walked iteratively via `genBiomeIndex` (bounded, `biomeCache`), drawn from its own `R('biome', g)` stream so the music seeds are untouched. `genParams(g)` is central: one generation = one "movement" with its own mode, meter, tempo, chord span, bell loops, weather (birds/crickets follow UTC time of day; ~1 in 5 generations rains — `P.rain` drives the audio layer and the overcast/cloud/drop visuals, and quiets birds/crickets; days share a tonal centre via the `'day'` seed), melody register (`melShift`), arrangement (`enters`: melody/bass/bells/arp/ostinato join staggered through the first half, scaled to the generation's `len`, gated via `layerLevel`; `outroDur` = min(120 s, 15% of len) thins melody/arp/ostinato at the close), an ostinato figure (`ostPat`: steps index into the sounding chord's degrees; `ostVoice` picks its instrument — the pluck kit's other half, or a sung/struck archetype (sine / triangle / hollow square / FM e-piano / marimba / breath) branched in `playOstTone`, extras seeded by `R('ostv', g)`), and a **timbre block** (`P.timbre`, seeded by `R('timbre', g)`): per-voice envelope/filter/waveform variation, a pad voice archetype (`timbre.pad.voice`, own `R('padv', g)` stream: duo / saw ensemble / pitch-wobble / breathing-filter / organ stack — branched in `playPad`), a reverb-send multiplier (`verb`), and delay settings (`delay.time` pulse-locked, `delay.fb`, `delay.amt` — ~30% of generations are delay-free). Cutoffs are deliberately capped low (soft sources into long reverb; nothing glassy). Cached in `genCache` (LRU, 80 entries).
4. **`js/voices.js` — the sounds** — Web Audio graph plumbing (buses, sends) and every instrument. Signal flow: voices → `dryBus`/`wetBus` → per-generation tone lowpass (`toneDry`/`toneWet`, matched pair, cutoff = `genParams().toneHz`, placed pre-reverb so the tail is filtered too) → convolution reverb (wet side) → warm lowpass → compressor → analyser → master. A global feedback delay (`delayBus` → `delayNode` → in-loop lowpass → `delayFb`) is fed per voice via `sendDelay()` and retuned per generation in `setTone()` (snapped in `tuneIn()`); its output re-enters the normal dry/wet buses so echoes wear the same tone/reverb. Voice functions (`playPad`, `playTone`, `playBell`, `playBass`, `playPluck`, `playKalimba`, `playChirp`, `playCricket`) read `P.timbre`; bells run through a dedicated lowpass and drop any partial above 3 kHz (they read glassy otherwise). Persistent layers: drone, wind, water, rain (`rainLayer`: a hiss bed plus two seeded droplet loops — sparse close drops and dense patter, rendered offline by `makeDropLoop` and phase-locked to wall time — under slow swell LFOs; `setWeather` sets the master level and rebalances the strands so light rain is distinct drops, heavy rain a wall of hiss). The plucked string is Karplus-Strong rendered offline into cached buffers keyed by pitch+damping (`pluckBuf(midi, damp)`) — never build per-note live feedback loops; they accumulate forever on an endless broadcast (the single global delay with fb < 0.5 is fine). One-shot sources register via `startNode()` into `liveNodes` so `cutLiveNodes()` can silence everything on a time jump. (Note: the buses/`master`/`analyser` are declared here but *built* in `scheduler.js`'s `start()`.)
5. **`js/melody.js` — what plays, when** — the compositional decisions as pure data. Layers breathe via `layerLevel` (entry stagger) and **phrase gates** (`phraseGate(P, key, tw, win, onProb)`: seeded per-window on/off with short crossfades — melody ~2 min, arp ~100 s and lifting when the melody rests, bass ~140 s, bells ~150 s, ostinato ~5 min; the pad gates whole chords via `padOn(P, chordStartTw)`, window 0 always on). `pulseEvents(P, p, tw)` is the heart: a pure function returning the note event objects one pulse produces (`pad`/`bass`/`mel`/`mpluck`/`arp`/`ost`/`bell`), which the scheduler plays and the midi roll re-derives — **any new or changed voice must go through `pulseEvents`** (plus `KIND_TRACK`, and `ROLL_TRACKS` in `roll.js`) or the roll stops matching the audio. Also owns `rollMute`/`KIND_TRACK` (the track taxonomy).
6. **`js/scheduler.js` — the transport** — `tick()` runs every 400 ms and pre-schedules `LOOKAHEAD` (2.5 s) of audio via `scheduleRange(w0, w1)`, which walks the pulse grid per generation (`genAt`/`genAfter`) and calls `schedulePulse` (which plays each `pulseEvents` result and pushes to `visQueue`). Birds/crickets live on a separate 4-second lattice; `slotAt(s)` makes the leading RNG draws (slot offset, bird presence) reproducible for the roll while the returned stream continues into the chirp — keep that draw order. Also owns `start()` (builds the graph into voices.js's bus bindings), `tuneIn()`, and `retune()`.
7. **`js/visual.js`** — canvas 2D render loop. The current generation's `P.biome` selects an **environment** from `BIOME_RENDER` — `hills` (five analyser-driven ridgeline layers, drift's original), `ocean` (low sun over water with a shimmering glitter column and fbm wave banding), `forest` (layered conifer canopies fading into haze, framed by near trunks whose foliage is seeded per-index via `ih` — fir / broadleaf / bare-snag), `coast` (a high coastal overlook: a broad calm sea under a low sun, distant hazy capes on the horizon (`drawHeadland`), and a grassy hero sea-cliff in the near foreground (`drawSeaCliff`) whose eroded, cracked rock face plunges to the water, planted with windswept trunked pines that lean out to sea (`drawCoastTree`), scrub mounds, grass tufts, and orange lilies, plus a framing foreground grass mound — its whole layout, incl. an optional mirror flip, is seeded off the generation id `g` via `ih`, so each coast movement composes differently yet reproducibly; `drawSeaCliff` returns the top-profile fn so scenery roots exactly on the grass line; grass cools toward moonlit blue-grey at night), or `snow` (the most minimal biome: a crisp cold-tinted sky, a pale low sun, a few soft low-contrast snow-drift ridges, and a sparse per-generation-seeded stand of bare recursive saplings — planted between the mid and near drifts so the front bank grounds their feet — under quietly drifting flakes; near-monochrome, cooling to moonlit blue-grey at night), or `sky` (the most weightless biome: no land at all, just an open cloudscape — a high centred sun and a few parallax layers of soft cumulus (`drawCumulus`, puffy-topped with a flat base, lit top → shaded under) drifting past with lots of open air between, seeded per generation; birds ride in via the shared note overlays). Biome renderers may read a 7th arg `g` (the generation id) for such per-generation variation. All share the paper-toned sky whose day/night tint follows UTC hour, the breathing fractal-noise sun (`drawSun`, which the sky keyframes pale into a moon at night), and pad rings (`drawPadRings`). Reactivity is analyser-driven and per-biome (sun breathes on the lows, ocean glitter sparkles on the highs, canopy/waves swell on the mids), scaled by `visIntensity`. At a generation seam the previous biome is rendered to an offscreen twin (`xcanvas`) and dissolved over the new one for `XFADE` seconds — keyed off `P.start`, so the morph is synchronized worldwide. Shared overlays on top: weather (`drawClouds`/`drawRain`, gated by `P.rain`) and note shapes (triangle=melody, diamond=bell, square=bass, vertical tick=pluck, dot=bird) placed horizontally by circle-of-fifths pitch (`pitchX`). Consumes `visQueue`. **Any new biome must go in `BIOME_RENDER` keyed by an id in structure.js's `BIOME_IDS`, and take `(ctx, t, sky, sun, night, dayness)` so it can also render to the offscreen twin.**
8. **`js/ui.js` — ui / debug** — now-playing readout, volume, and the debug panel: time-travel offsets, jump-to-datetime, "new generation" (skips to the next segment), a per-track mixer (vertical faders for every track incl. sfx — drives `setMixLevel()` in voices.js, which scales that track's mixer taps: shared gains between each voice's per-note dry/wet/delay send gains and the buses, tagged via the `track` argument to `out`/`outSfx`/`sendDelay`; local ears only, the broadcast is untouched), and the upcoming-generations audition table (start time + duration per row). Any time jump goes through `jumpTo()` → `retune()` (cut live nodes, clear queues, invalidate the roll cache, `tuneIn()` into the new moment).
9. **`js/roll.js` — midi roll** — daw-style audit panel (`m` key, `?roll`, or the debug panel's "midi roll" button): one named lane per layer (birds, bells, melody, arp, ostinato, pad, bass, drone) with a playhead, bar/chord/generation gridlines, chord numerals, and pre-entry/outro shading. It re-derives events via `auditEvents(w0, w1)` (same walk as `scheduleRange`, nothing played) into a cached window (`roll.evs`), so it can draw the future as well as the past. Clicking a lane name mutes that track **locally only** (event tracks gate in `schedulePulse` and take effect within `LOOKAHEAD`; drone/birds duck dedicated gains — `drone.gain`, `birdBus`) — the broadcast stream itself is never altered. Lane colors (`ROLL_INK`) are day/night pairs blended by `inkTNow`, palette-validated against both the paper and deep-night sky surfaces.
10. **`js/main.js` — bootstrap** — loaded last, once every other concern is defined: global keybindings (`` ` `` debug, `m` roll), `?debug`/`?roll` query-param handling, and the once-a-second now-playing refresh. New global wiring that depends on many files belongs here.

## Gotchas

- `tuneIn()` handles entering the broadcast mid-chord: it computes the chord already sounding and plays it with a shortened attack/duration, so joins and time-jumps don't start from silence (skipped when `padOn` says the pad is resting on that chord — the join must match the broadcast). It also snaps the tone filters and delay time/feedback to the current generation's values (no glide).
- `scheduleRange` clamps pulses to their generation (`t >= P.start + P.len` breaks), so generations never bleed into each other even though pulse grids don't divide segment lengths evenly.
- The `visQueue` is not time-ordered; the frame loop scans the whole queue each frame.
- Master volume is `volume² × 0.9` (perceptual curve) — set in three places: `start()`, the volume input handler, and `cutLiveNodes()`'s restore ramp. Keep them consistent.
