# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**drift** — a continuous generative music broadcast in the browser. Two files, no build step, no dependencies, no framework:

- `index.html` — page shell, all CSS, UI chrome (masthead, now-playing colophon, debug panel, "tune in" veil)
- `app.js` — everything else: time model, deterministic RNG, music theory, Web Audio synthesis, scheduler, canvas visuals, UI wiring

Run it by opening `index.html` in a browser (or any static server, e.g. `python3 -m http.server`). Audio requires a user gesture, so playback starts via the "tune in" button. Append `?debug` to the URL (or press `` ` ``) to open the debug panel.

## Core invariant: determinism from UTC time

Every musical and visual event is a **pure function of UTC wall-clock time** so that all listeners worldwide hear the identical moment of the same endless piece. This is the load-bearing design rule — preserve it in any change:

- All randomness must come from the seeded PRNG helpers (`R`, `rand`, `pick`, `wpick`, `vnoise`), keyed by stable identifiers like generation id / pulse index (e.g. `rand('ml', g, p)`). Never use `Math.random()` for anything audible or musically meaningful (it's only used for noise/impulse buffer sample data, where the exact samples don't matter).
- Time is expressed in seconds since `ORIGIN` (broadcast epoch, 1 Jan 2026 UTC) via `wallNow()`, which includes `debugOffset` for simulated time travel. Always use `wallNow()`, never `Date.now()` directly, for anything musical or visual.
- Broadcast time is converted to AudioContext time by adding `ctxOff` (recomputed each tick).

## Architecture

Structure of `app.js`, in order (sections are marked with `/* --- name -- */` comment banners):

1. **time** — `ORIGIN`, `wallNow()`, `debugOffset`
2. **deterministic randomness** — xmur3/mulberry32 PRNG, string-keyed helpers for music; separate fast integer-hash noise (`ih`, `vn`, `fbm`) for per-frame visuals (avoids string hashing per frame — keep that split)
3. **theory** — modes, odd meters, euclidean rhythms. **Generations**: each UTC hour is deterministically cut into 2–5 segments of 10–30 minutes that tile it exactly (`hourSegs(e)`, feasibility-clamped draws); a generation's id is `hourIndex * GEN_SLOTS + segmentIndex`. `genAt(w)` finds the segment sounding at broadcast time `w`; `genAfter(g)`/`genSeg(g)` iterate/resolve segments. `genParams(g)` is central: one generation = one "movement" with its own mode, meter, tempo, chord span, bell loops, weather (birds/crickets follow UTC time of day; days share a tonal centre via the `'day'` seed), melody register (`melShift`), arrangement (`enters`: melody/bass/bells/arp/ostinato join staggered through the first half, scaled to the generation's `len`, gated via `layerLevel`; `outroDur` = min(120 s, 15% of len) thins melody/arp/ostinato at the close), an ostinato figure (`ostPat`: steps index into the sounding chord's degrees), and a **timbre block** (`P.timbre`, seeded by `R('timbre', g)`): per-voice envelope/filter/waveform variation, a reverb-send multiplier (`verb`), and delay settings (`delay.time` pulse-locked, `delay.fb`, `delay.amt` — ~30% of generations are delay-free). Cutoffs are deliberately capped low (soft sources into long reverb; nothing glassy). On top of entry stagger, layers breathe on **phrase gates** (`phraseGate(P, key, tw, win, onProb)`: seeded per-window on/off with short crossfades — melody ~2 min, arp ~100 s and lifting when the melody rests, bass ~140 s, bells ~150 s, ostinato ~5 min; the pad gates whole chords via `padOn(P, chordStartTw)`, window 0 always on). Cached in `genCache` (LRU, 80 entries). `chordAt(g, ci, P)` derives chords deterministically per generation+index.
4. **audio** — Web Audio graph: voices → `dryBus`/`wetBus` → per-generation tone lowpass (`toneDry`/`toneWet`, matched pair, cutoff = `genParams().toneHz`, placed pre-reverb so the tail is filtered too) → convolution reverb (wet side) → warm lowpass → compressor → analyser → master. A global feedback delay (`delayBus` → `delayNode` → in-loop lowpass → `delayFb`) is fed per voice via `sendDelay()` and retuned per generation in `setTone()` (snapped in `tuneIn()`); its output re-enters the normal dry/wet buses so echoes wear the same tone/reverb. Voice functions (`playPad`, `playTone`, `playBell`, `playBass`, `playPluck`, `playKalimba`, `playChirp`, `playCricket`) read `P.timbre`; bells run through a dedicated lowpass and drop any partial above 3 kHz (they read glassy otherwise). Persistent layers: drone, wind, water. The plucked string is Karplus-Strong rendered offline into cached buffers keyed by pitch+damping (`pluckBuf(midi, damp)`) — never build per-note live feedback loops; they accumulate forever on an endless broadcast (the single global delay with fb < 0.5 is fine). One-shot sources register via `startNode()` into `liveNodes` so `cutLiveNodes()` can silence everything on a time jump.
5. **scheduler** — `tick()` runs every 400 ms and pre-schedules `LOOKAHEAD` (2.5 s) of audio via `scheduleRange(w0, w1)`, which walks the pulse grid per generation (`genAt`/`genAfter`) and calls `schedulePulse`. All note decisions live in `pulseEvents(P, p, tw)` — a pure function returning event objects (`pad`/`bass`/`mel`/`mpluck`/`arp`/`ost`/`bell`) that `schedulePulse` plays and the midi roll re-derives; **any new or changed voice must go through `pulseEvents`** (plus `KIND_TRACK`/`ROLL_TRACKS` for the roll) or the roll stops matching the audio. Scheduling a note also pushes an event to `visQueue` (broadcast-time-stamped) for the visuals. Birds/crickets live on a separate 4-second lattice; `slotAt(s)` makes the leading RNG draws (slot offset, bird presence) reproducible for the roll while the returned stream continues into the chirp — keep that draw order.
6. **visual** — canvas 2D render loop: paper-toned sky whose day/night tint follows UTC hour, breathing fractal-noise sun, five ridgeline layers driven by analyser frequency bands, and note shapes (triangle=melody, diamond=bell, square=bass, vertical tick=pluck, dot=bird) placed horizontally by circle-of-fifths pitch position (`pitchX`).
7. **ui / debug** — now-playing readout, volume, and the debug panel: time-travel offsets, jump-to-datetime, "new generation" (skips to the next segment), upcoming-generations audition table (start time + duration per row). Any time jump goes through `jumpTo()` → `retune()` (cut live nodes, clear queues, invalidate the roll cache, `tuneIn()` into the new moment).
8. **midi roll** — daw-style audit panel (`m` key, `?roll`, or the debug panel's "midi roll" button): one named lane per layer (birds, bells, melody, arp, ostinato, pad, bass, drone) with a playhead, bar/chord/generation gridlines, chord numerals, and pre-entry/outro shading. It re-derives events via `auditEvents(w0, w1)` (same walk as `scheduleRange`, nothing played) into a cached window (`roll.evs`), so it can draw the future as well as the past. Clicking a lane name mutes that track **locally only** (event tracks gate in `schedulePulse` and take effect within `LOOKAHEAD`; drone/birds duck dedicated gains — `drone.gain`, `birdBus`) — the broadcast stream itself is never altered. Lane colors (`ROLL_INK`) are day/night pairs blended by `inkTNow`, palette-validated against both the paper and deep-night sky surfaces.

## Gotchas

- `tuneIn()` handles entering the broadcast mid-chord: it computes the chord already sounding and plays it with a shortened attack/duration, so joins and time-jumps don't start from silence (skipped when `padOn` says the pad is resting on that chord — the join must match the broadcast). It also snaps the tone filters and delay time/feedback to the current generation's values (no glide).
- `scheduleRange` clamps pulses to their generation (`t >= P.start + P.len` breaks), so generations never bleed into each other even though pulse grids don't divide segment lengths evenly.
- The `visQueue` is not time-ordered; the frame loop scans the whole queue each frame.
- Master volume is `volume² × 0.9` (perceptual curve) — set in three places: `start()`, the volume input handler, and `cutLiveNodes()`'s restore ramp. Keep them consistent.
